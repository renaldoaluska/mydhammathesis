[7] KEPUTUSAN
--------------------------------------------------------------------------------
TIDAK retrain untuk versi ini. Tidak ada bug (§5); tetapi HASIL = GPL tidak
memberi manfaat ekstrinsik dan SIGNIFIKAN menurunkan P@5. Narasi yang dipakai
(jujur & defensible):
  "GPL terbukti meningkatkan kualitas geometri embedding (separabilitas intra/inter-
   sutta) secara substansial, NAMUN pada evaluasi relevansi terjilid-pakar untuk temu-
   kembali Pali berbahasa Indonesia, GPL TIDAK memberi peningkatan: precision@5 justru
   SIGNIFIKAN lebih rendah dari base (Wilcoxon p=0.024; sign-test gabungan p=0.034),
   sedangkan nDCG@5 & Spearman cenderung negatif namun belum signifikan. Efeknya
   bergantung model: gpl-gte setara base, gpl-e5 regres. Diverifikasi-silang oleh dua
   LLM-judge yang mereproduksi peringkat pakar (kappa 0.61 vs 0.46)."
Kontribusi tetap: sistem temu-kembali + metodologi evaluasi multi-asesor (pakar +
LLM-judge + IAA + intrinsik) + temuan negatif yang solid (GPL apa-adanya tak cocok utk
domain ini tanpa perbaikan resep).


[8] JIKA INGIN IMPROVE (future work)
--------------------------------------------------------------------------------
(8a) DARI BASE ATAU DARI GPL? -> perbaiki RESEP lalu LATIH ULANG DARI BASE, bukan
menumpuk di atas checkpoint GPL:
  - GPL = "base + 1 putaran GPL"; melatih lagi di atasnya menumpuk drift sama + risiko
    catastrophic forgetting kemampuan retrieval base.
  - Base relevansi ekstrinsik lebih tinggi (§2) -> titik mula lebih bersih.
  - Ablation lebih terkontrol untuk tesis.

(8b) "PAKAI LABEL PAKAR JADI SUPERVISED?" -> HATI-HATI, ini risiko utama:
  - KEBOCORAN (leakage): label pakar = test set. Melatih lalu eval pada 30 kueri yang
    SAMA mengukur hafalan, bukan generalisasi -> klaim eval runtuh.
  - Jika tetap supervised, WAJIB held-out di level KUERI (mis. 5-fold: latih 24, uji 6).
    Tapi n=30 terlalu kecil -> sinyal minim, varians besar, tak meyakinkan.
  - Juga menyabot motivasi tesis (GPL dipilih KARENA label domain langka/mahal).
  ALTERNATIF BERSIH (disarankan): jadikan LLM-judge sinyal latih yang scalable
  (Claude/Gemini berkorelasi pakar, kappa 0.61, §4) -> hasilkan label murah utk RATUSAN
  kueri sebagai data latih/distilasi; 30 kueri pakar DISIMPAN sebagai test held-out
  yang tak pernah disentuh latihan. Train/test terpisah bersih, tanpa leakage.

  MEKANISME KONKRET — DATA LATIH DARI LLM BESAR (arah paling menjanjikan, v2):
  Gunakan frontier-LLM untuk membangun data latih, menyasar 2 kelemahan terdiagnosa:
    (i)  GENERATOR KUERI: ganti GPL_QUERY_GEN (T5 kecil) dgn LLM yang menulis pertanyaan
         ID NATURAL dari tiap pasase. ROI tertinggi -> memperbaiki mismatch kueri-
         sintetis vs natural yang paling melukai e5 (§3).
    (ii) TEACHER RELEVANSI: LLM memberi grade/margin -> ganti/augment cross-encoder
         teacher dgn penilai lebih sadar-domain.
  Teknik baku (cf. [REFERENSI] InPars/Promptagator/distilasi LLM). RAMBU WAJIB:
    - LEAKAGE: data latih LLM HARUS pada kueri/pasase LAIN; 30 kueri pakar + pasasenya
      DIKECUALIKAN dari generasi -> tetap test held-out murni.
    - BIAS 1-LLM: Gemini timpang (58% grade-3); pilih teacher terkalibrasi (Claude lebih
      seimbang) / ensemble / skor soft.
    - Nondeterministik + biaya: BEKUKAN dataset hasil generate (spt grades_*.json), lalu
      LATIH ULANG DARI BASE (lihat 8a).
  Status: eksperimen v2 (generate -> retrain -> re-eval), BUKAN tweak.

(8c) CARA IMPROVE RESEP UNSUPERVISED (urut ROI; regen GPL dari base):
  1. HARD-NEGATIVE lebih bersih (ROI tertinggi). Teks Buddhis banyak pericope/formula
     berulang lintas-sutta -> ke-mine sbg "negatif" padahal relevan = false-negative
     yang mengajarkan margin salah. Fix: filter berbasis margin, de-dup near-duplicate.
     [konteks kode: src/code/4-training/2-hard-neg.py]
  2. TEACHER lebih kuat. Cross-encoder teacher menentukan margin; bila generik & lemah
     di Pali/Buddhis-ID -> margin berisik. [konfig: src/config.py GPL_CROSS_ENCODER]
  3. KUERI sintetis lebih natural (khusus e5). e5 (terkondisi prefix kueri) paling
     sensitif thd mismatch train/eval -> menjelaskan §3. [konfig: src/config.py GPL_QUERY_GEN]
  4. HYPERPARAM lebih lembut: kurangi GPL_STEPS/LR utk batasi drift. NB: ablasi exp1
     (5000 steps) TIDAK memulihkan base & tetap ~setara GPL -> langkah bukan pengungkit
     utama (lihat 8-reeval/exp1). [konfig: src/config.py GPL_STEPS]
  5. STRATEGI per-model: gpl-gte sudah ~setara base; opsi pragmatis pertahankan e5-base
