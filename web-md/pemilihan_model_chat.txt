4. PERBAIKAN PIPELINE CHAT  (2026-06-16, terkait kualitas jawaban)
--------------------------------------------------------------------------------
Banyak gejala "model ngawur/ga dengerin prompt" ternyata BUKAN murni model:

  a) num_ctx (BIANG UTAMA): Ollama default 2048 -> prompt RAG (system +
     answer-guide + 9+ passage + reminder) kepotong diam-diam DARI DEPAN ->
     passage terbaik (mis. AN 9.64 yg ngelist lengkap) kebuang -> model cuma
     lihat ekor prompt -> under-answer. FIX: CHAT_NUM_CTX=8192 di semua call
     Ollama (_ollama_json, _ollama_chat, _ollama_stream); harus SAMA di semua
     call (beda num_ctx = Ollama reload model tiap request).

  b) Kartu sumber (_cited_only): dulu kartu = HANYA sutta yg di-kutip model di
     teks. Kalau model salah kutip, sumber asli ILANG. FIX: (1) word-boundary
     regex (cegah "DN 2" cocok di "DN 22"); (2) PAD kartu dgn kandidat retrieval
     skor tertinggi -> sumber real tetap tampil walau model salah/lupa kutip.

  c) Diakritik Pali: model kecil sering nulis tanpa diakritik (satipatthana,
     nibbana). FIX: map normalisasi (_PALI_DIACRITIC_MAP di app.py +
     enforceTheravadaTerms di static/chat.js) -> satipatthana -> satipatthana[diakritik],
     metta -> metta[diakritik], dst. Kurasi rendah-tabrakan (TANPA sila/mara/nana).

  d) Follow-up context (deiktik): kalau user merujuk balik ("...di sutta itu?")
     tapi LLM lupa nyelipin kode sutta, kartu drift ke sutta lain. FIX: carry
     kode sutta dari giliran asisten terakhir HANYA kalau ada pola deiktik
     (referent-noun + kata tunjuk: "sutta itu", "teks tersebut", "di situ");
     idiom "apa itu X" sengaja TIDAK memicu (anti lock-in).

  e) Enumerasi (granularity): kueri "sebutkan/empat jenis ..." butuh daftar
     UTUH. FIX: _ENUM_INTENT_RE -> _passages_for_prompt ambil 8 chunk (bukan 5)
     & cap 3200 char (bukan 2000), biar list lengkap kebawa.

  f) Temperature jawaban final diturunkan 0.45 -> 0.35 (kurangi wandering).

5. SURVEI MULTI-SKEMA ENUMERATIF  (SUDAH SELESAI — 2026-06-16)
--------------------------------------------------------------------------------
Kasus: "empat jenis manusia" punya beberapa kategorisasi berbeda isi (siksa
diri/orang-lain, apa yg dihargai, tingkat kecelaan, cara memahami, status di
Sangha, kearifan, dst). Dulu model collapse ke SATU skema dominan.

DIAGNOSIS (penting): bottleneck-nya BUKAN retrieval kurang ragam — passage yg
dikirim ke model SUDAH beragam. Masalahnya POSISI ATENSI instruksi: klausa SURVEI
di answer-guide kependem di tembok teks -> diabaikan model.

FIX yang berhasil: inject pengingat enum-survei di REMINDER AKHIR (di-append ke
pesan tool terakhir = atensi tertinggi), DAN hanya saat _ENUM_INTENT_RE match,
DENGAN guard anti-ngarang ("kalau cuma ada satu skema, bahas satu saja").
Hasil di qwen3:14b: jawaban kini menyurvei 5-6 skema BERBEDA, masing-masing
dengan sutta + sitasi segmen, dan ISINYA AKURAT (bukan halusinasi).
=> query-expansion yg dulu direncanakan TIDAK jadi perlu.

Catatan: kadang ada sedikit redundansi sub-bullet (minor). Faithfulness tetap
dijaga oleh guard + sifat qwen3 (beda total dgn gemma yg ngarang skema palsu).
